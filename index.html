CV Quantization & Compilation Pipeline

YOLOv8 to NPU

To run object detection under 40ms on the edge, the fine-tuned YOLOv8n network undergoes strict post-training quantization (PTQ) and model compilation:

  • Dataset Fine-tuning: Trained on 4,200 custom labeled images (640x640 resolution) representing the deployment warehouse corridor, using mosaic augmentation and mixed-precision optimization.
  • Quantization to INT8: Performed with Hailo Model Zoo tools using a representative calibration subset of 300 frames. This compresses model weight precision from FP32 to INT8, resulting in a minor 0.9% drop in mAP.
  • HEF Compilation: The compiled HEF (Hailo Executable Format) specifies optimized register-level data routings tailored specifically to the physical internal processor structure of the Hailo-8L NPU.

Ray-Casting & Kalman Tracking

Algorithmic Base

The tracking system runs two mathematically optimized algorithms directly on the Pi 5's ARM CPU:

ByteTrack (Stateful Association) Utilizes a Kalman Filter to model target trajectory motion velocity, matching low-score detections in the second step to handle brief physical occlusion behind warehouse pillars.
Ray-Casting Polygon Intersection Determines zone containment by casting a horizontal ray from the object's bottom-center coordinate. Checking coordinate crosses against polygon borders runs in O(N) where N is the number of vertices.

Zero-Copy Shared-Memory Ring Buffer

Zero-Copy Engine

Standard Python subprocess pipelines face major execution bottlenecks due to inter-process communication serialization. To fix this, our pipeline leverages POSIX shared-memory blocks (`multiprocessing.shared_memory`). Decoded raw camera pixel frames write directly to a shared RAM circular buffer, allowing concurrent zero-copy access by the worker thread.

Recording & Clip Trimming

Local Pipeline

Instead of active video encoding on the constrained Pi 5 CPU, the platform writes the raw H.264 stream into continuous rolling 5-minute segments on the local NVMe drive.

  • Stream copy clip extraction: When a CV zone event is triggered, a background worker uses FFmpeg stream-copy: `ffmpeg -ss -to -c copy` to slice the ±15-second block around the timestamp. Slicing completes in under 1 second since it doesn't execute re-encoding.
  • Network isolation queues: Raw sliced clips are queued in a persistent SQLite buffer database, ensuring video files are preserved during network blackouts.

Cloud Transcoding Offloader

Clips are uploaded raw to Amazon S3. An AWS Lambda event trigger spins up FFmpeg inside a serverless container to transcode the video to optimized H.264/AAC MP4 & HLS (.m3u8) streams. This offloads compute-heavy transcoding entirely from the edge device.

systemd Hardening & Watchdogs

Security Hardening

The application runtime is configured as a system daemon that leverages systemd's sandboxing mechanics. This prevents host compromise even if the Python process is breached:

  • Hardware Watchdog: Configured with `WatchdogSec=30`. The Python event loop is required to send heartbeats (`systemd.daemon.notify`) at regular intervals. Failure to heartbeat within the window triggers a hard system daemon restart.
  • Sandbox Controls: Restricts operations using kernel sandboxing options: `ProtectSystem=strict` makes the root OS filesystem read-only, `ProtectHome=true` isolates user home directories, and `PrivateDevices=false` selectively exposes only specific system devices (like `/dev/hailo0` and PCIe lanes).

Automated Provisioning & WireGuard

Operations Management

Managing multiple edge cameras requires reproducible deployment and secure remote maintenance. The platform relies on a dual-layer remote orchestration model:

Ansible Playbook Deployment Automates system setup: compiles the kernel driver, mounts nvme storage partitions, configures Python dependencies, and deploys systemd units.
WireGuard Overlay Mesh Network Establishes a split-tunnel encrypted link directly to a central cloud server, bypassing NAT and firewalls to allow secure SSH management access.
Automated Logging & Metrics System journal logs are continuously streamed to AWS CloudWatch via a background Vector agent, enabling centralized monitoring.

Reliability & Metrics Tracking Architecture

Uptime Engine

Continuous telemetry profiling ensures early detection of resource constraints or algorithmic performance degradation. Metrics were tracked at every deployment stage:

  • Automated Regression Testing: Each software release compiles models inside a containerized ARM simulator, comparing target mAP scores against a golden evaluation dataset to block regression.
  • Production Performance Audits: Host device telemetry is monitored via a local Prometheus node. If RAM utilization exceeds 2.5 GB, an alert fires to notify cloud operators.
